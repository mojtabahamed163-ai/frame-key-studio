# تقرير إصلاحات الاستقرار — Frame & Key Studio

**التاريخ:** 2026-10-18

## النتيجة المختصرة

أُصلحت أخطاء مؤكدة في مسار قبول المصدر، التصدير، الإلغاء، والتوازي دون إعادة بناء التطبيق ودون إضافة خدمة مدفوعة أو رفع للفيديو. أضيفت الآن اختبارات Playwright قابلة لإعادة التشغيل بوسائط محلية مولدة، لكن النتيجة لا تزال ليست إعلانًا عن جاهزية مطلقة أو 100%.

## الملفات التي تغيرت

- `client/src/features/studio/media/analyze-video.ts`: حدود المصدر والتحقق المبكر للملف والمدة والدقة.
- `client/src/features/studio/media/analyze-video.test.ts`: اختبارات الملف الفارغ والصيغة غير المدعومة والحجم والمدة والدقة والفيديو الصامت.
- `client/src/features/studio/export/convert-clip.ts`: إزالة سجلات debug، ورفض artifact الفارغ، والتحقق من metadata لملف Blob بمهلة.
- `client/src/features/studio/export/convert-clip.test.ts`: اختبار عدم إعلان نجاح ملف تصدير فارغ.
- `client/src/pages/Studio.tsx`: زر إزالة المصدر، عرض نطاق الدعم، إلغاء كشف الوجه، منع توازي العمليات الثقيلة، رسائل الإلغاء، وRetry صريح للتحليل والترجمة وكشف الوجه والتصدير.
- `README.md`: حدود التشغيل والخصوصية والتشغيل المحلي.
- `TODO.md` و`docs/continuation-handoff-2026-10-18-ar.md`: سجل الأدلة والقيود المتبقية.
- `playwright.config.ts` و`e2e/studio.spec.ts` و`scripts/create-test-media.sh`: اختبارات E2E وfixtures قابلة لإعادة التوليد.

## الحدود الحالية المطبقة

النطاق الأساسي هو MP4/H.264 حتى 1080p، مدة لا تتجاوز 30 دقيقة، وحجم لا يتجاوز 1 GB. الفيديو الصامت مقبول للقص اليدوي والتصدير، لكن تحليل الكلام يحتاج مسارًا صوتيًا. الصيغ الأخرى لا تُرفض جميعها إذا قرأها decoder المتصفح، لكنها ليست مضمونة. 4K خارج النطاق المستقر. المصدر لا يُرفع إلى الخادم، ولا يُحفظ محليًا بعد إغلاق الصفحة إلا إذا اختار المستخدم حفظه اختياريًا في OPFS؛ ملاحظات المشروع والإعدادات والتفريغ تُحفظ في IndexedDB.

## الوظائف التي تم إصلاحها

يُرفض الملف الفارغ أو غير الفيديو أو الملف الأكبر من الحد قبل المعالجة الثقيلة، وتُرفض المدة والدقة غير المدعومتين بعد قراءة metadata. يعرض الاستوديو النطاق المدعوم بدل الاكتفاء بتحذير عام. يمكن إزالة المصدر بوضوح بعد حفظ لقطة المشروع الحالية، ويبقى المشروع المحلي متاحًا لإعادة الفتح.

لا يُوسم التصدير الجاهز قبل التأكد من وجود بيانات مكتوبة، ويفحص Blob الناتج قابلية قراءة metadata عبر عنصر فيديو عندما تتاح واجهات المتصفح. أزيلت سجلات Console التي كانت تطبع حجم الملف وتفاصيل التصدير وstack trace. أصبح إلغاء تحليل الكلام والترجمة وكشف الوجه مرئيًا، مع زر إلغاء لكشف الوجه، ورسالة تشرح أن المدخلات بقيت. لا يمكن بدء عمليات ثقيلة متزامنة، وتوجد إعادة محاولة صريحة دون فقد المصدر أو الإعدادات.

## الاختبارات والنتائج

- `pnpm check`: ناجح.
- `pnpm test -- --run`: ناجح؛ **13 ملف اختبار و122 اختبارًا ناجحًا، 0 فاشل**.
- `pnpm build`: ناجح.
- `git diff --check`: ناجح.
- `pnpm test:e2e`: ناجح؛ **6 اختبارات Chromium، تشمل رفض ملف غير فيديو، رفض 2048×1152، رفض 1801 ثانية، رفع فيديو فعلي، قص 9:16، تصدير وتنزيل وفحص FFprobe، إعادة فتح المشروع المحفوظ، وواجهة هاتف 390×844 بلا overflow أفقي**.
- ناتج التصدير في E2E كان ملفًا غير فارغ يحوي stream فيديو ومدة موجبة وفق FFprobe.
- `GET /manus-routes.json`: ناجح بحالة HTTP 200، والمساران `/` و`/studio` موجودان.
- نموذج التفريغ الحالي: `Xenova/whisper-tiny`.

يظهر في البناء تحذير غير مانع عن script `/api/platform/config.js` غير المعرّف كـmodule، وتحذير عن بعض chunks الأكبر من 500 kB. لم يمنع أي منهما البناء أو الاختبارات.

## ما لم يُختبر بعد

نجحت اختبارات Chromium وواجهة هاتف محاكاة فقط؛ لم يُنفذ بعد تشغيل Firefox أو Safari/WebKit الحقيقي أو جهاز Android/iPhone فعلي. فُحص ناتج تصدير واحد بـFFprobe، ولم يُنفذ بعد تصدير كل التركيبات أو اختبار ZIP واقعي متعدد المقاطع. كما لم تُضف بعد واجهات الحفظ اليدوي، تصدير/استيراد JSON، حذف كل بيانات التطبيق، أو رسائل QuotaExceededError المتخصصة. الترجمة وكشف الوجه والإلغاء وإعادة المحاولة ما زالت مدعومة باختبارات الوحدة وحواجز الكود، لكن لم يُشغّل E2E كامل ينتظر نموذج Whisper أو نموذج الوجه ثم يلغي ويعيد المحاولة.

## التقييم الصادق

الإصلاحات الحالية تغلق عيوبًا موضعية مهمة، لكنها لا تبرر إعلان النسخة مستقرة 95–100% قبل اختبار الملفات الواقعية وفحص FFprobe واختبارات المتصفحات والأجهزة. التقدير الحالي: **تحسن موضعي موثق، مع بقاء بوابة القبول الواقعية مفتوحة**. المشروع مناسب لمتابعة الاستخدام المحلي التجريبي ضمن الحدود المذكورة، وليس لإعلان ضمان شامل لكل الأجهزة والملفات.
